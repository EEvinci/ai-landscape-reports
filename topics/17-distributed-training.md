## 一、三大并行策略：数据并行、流水线并行、张量并行

大模型参数规模庞大，单卡显存与算力无法容纳完整训练过程，分布式并行成为必然选择。目前业界主流的三大并行策略各有分工，也各有局限。

### 1.1 数据并行（Data Parallelism, DP）

**原理**：每个 GPU 保存完整的模型副本，各自处理不同的数据子集，计算梯度后通过 AllReduce 等通信原语聚合梯度并更新参数。

**优势**：实现简单，易扩展，是最广泛使用的并行策略。ZeRO（Zero Redundancy Optimizer）通过分片优化器状态、梯度、模型参数，进一步降低单卡显存需求，ZeRO-3 可支持百亿参数模型在单卡受限环境下的数据并行训练。

**局限**：所有 GPU 必须存储完整模型副本，显存瓶颈明显；跨节点通信开销随 GPU 数量线性增长。

**适用场景**：模型能完整放入单卡显存、数据量大的场景，是万卡集群的基础并行维度。

### 1.2 流水线并行（Pipeline Parallelism, PP）

**原理**：将模型按层切分到不同 GPU，数据以 micro-batch 为粒度流经各阶段，形成流水线。经典方案如 GPipe、PP（1F1B）通过交错调度减少流水线气泡（Pipeline Bubbles）。

**优势**：每个 GPU 只需存储模型的部分层，显著降低显存占用，适合深层 Transformer 的垂直切分。

**局限**：存在流水线气泡导致 GPU 利用率不完全；阶段间数据依赖关系增加了实现复杂度；调度策略对性能影响敏感。

**适用场景**：模型层数多（数十乃至上百层）、单层参数量不足以触发张量切分的场景，常与 DP/TP 组合使用形成 3D 并行。

### 1.3 张量并行（Tensor Parallelism, TP）

**原理**：将单层权重矩阵（如 Attention 中的 QKV 投影或 FFN 层）按行/列维度切分到多个 GPU，计算后通过 AllGather 汇总结果。Megatron-LM 最早系统提出这一方法。

**优势**：显存降低效果最显著，是千亿参数以上模型训练的关键技术。

**局限**：通信开销极大，尤其在跨节点场景；切分策略与模型结构深度耦合；超过 8 路 TP 时边际收益递减明显。

**适用场景**：单层权重矩阵超大的场景（如大维度 Linear 层），通常与 PP 和 DP 组合使用。

**三者组合**：实际万卡级训练均采用 DP + PP + TP 的混合并行（3D Parallelism），在模型参数量、显存占用、通信效率和 GPU 利用率之间取得平衡。

## 二、分布式训练框架进展（2024–2025）

### 2.1 DeepSpeed（ZeRO-3）

微软 DeepSpeed 是目前生态最广的分布式训练框架，核心能力建立在 ZeRO 优化器三阶段分片策略之上：

- **ZeRO-1**：分片优化器状态
- **ZeRO-2**：分片优化器状态 + 梯度
- **ZeRO-3**：完整分片（优化器状态 + 梯度 + 模型参数），支持参数规模远超单卡显存

DeepSpeed 2024–2025 年持续迭代，重点方向包括：

- **MoE（混合专家）模型支持**：DeepSpeed-MoE 已在 Sparse Upcycling 等技术上落地，降低 9 倍推理成本同时保持收敛质量
- **3D 并行融合**：与 Megatron-LM 融合为 Megatron-DeepSpeed，支持更高效的 TP + PP + DP 组合
- **推理优化**：DeepSpeed-Inference 通过 kernel fusion 和量化加速推理部署

### 2.2 Megatron-LM

NVIDIA Megatron-LM 是大规模 Transformer 训练的事实标准框架，在张量并行和流水线并行上积累最深。其设计哲学是底层算子与并行策略高度优化，专注于训练场景的性能极致性。

2024–2025 年 Megatron-LM 持续更新，核心进展包括：
- **序列并行（Sequence Parallelism）**：解决超长上下文训练的显存问题，将序列维度切分到多卡
- **Selective Activation Recomputation**：选择性重计算策略，平衡显存与计算开销
- **FlashAttention 集成**：低显存注意力机制原生支持
- **MoE 扩展**：支持 Expert Parallelism（EP），与 TP/PP 组合支持稀疏大模型训练

### 2.3 FSDP2（Fully Sharded Data Parallel v2）

PyTorch 官方于 2024 年推出 FSDP2，是 FSDP v1 的全面重写。核心改进：

- 基于 **DTensor API** 表示参数切分，提供了更灵活、更易用的分片策略表达
- 修复了 v1 版本的若干性能短板，补齐了 TP/PP/EP 并行能力
- 原生支持 MoE 混合专家模型
- 分片策略与调度器解耦，支持细粒度配置

FSDP2 的定位是对标 DeepSpeed ZeRO-3 和 Megatron-LM，提供 PyTorch 原生的端到端分布式训练方案，降低对第三方框架的依赖。PyTorch 2.7+ 中 FSDP2 已进入稳定版本。

### 2.4 ColossalAI

ColossalAI 由 HPC-AI Tech 推出，主打"用配置文件替代代码修改"的易用性路线。其核心优势：

- 一套配置文件即可配置多维并行策略（DP/TP/PP）
- 集成了丰富的显存优化技术（gradient checkpointing、混合精度、算子融合）
- 支持 ChatGPT 流程的 RLHF 训练管道（ColossalAI-Chat）
- 生态涵盖从单卡到万卡的分布式训练场景

2024 年 ColossalAI 继续维护更新，其设计目标始终是降低分布式训练门槛，让开发者像本地开发一样完成大规模训练部署。

## 三、通信优化：NVLink、InfiniBand 与 RoCE

分布式训练中 GPU 间通信是核心瓶颈，不同互联技术在带宽、延迟、成本上差异显著。

### 3.1 带宽层级

| 互联技术 | 节点内带宽（双向） | 节点间带宽 | 典型应用 |
|---------|----------------|---------|---------|
| PCIe 4.0 x16 | ~64 GB/s | — | 基础多卡互联 |
| NVLink 4.0 | ~900 GB/s（8-link H100） | — | DGX节点内GPU互联 |
| InfiniBand HDR | — | 400 Gbps（双向~800 Gbps） | 跨节点RDMA |
| RoCE v2 | — | 100–400 Gbps | 数据中心以太网上的RDMA |

### 3.2 NVLink

NVIDIA NVLink 是节点内 GPU 互联的首选技术，H100 SXM5 配置下单机 8 卡通过 NVSwitch 全互联，GPU 间双向带宽达到 900 GB/s。相比 PCIe 4.0，带宽提升约 14 倍，是张量并行和节点内数据并行的关键基础设施。Grace-Hopper 超级芯片还通过 NVLink-C2C 实现 CPU-GPU 直连（900 GB/s），为统一内存地址空间提供基础。

### 3.3 InfiniBand HDR

InfiniBand HDR（200/400 Gbps）是超大规模集群跨节点互联的主流选择。其 RDMA（Remote Direct Memory Access）能力绕过操作系统内核，直接内存访问，延迟低至微秒级，是万卡集群 NCCL 通信的首选底层网络。

### 3.4 RoCE（RDMA over Converged Ethernet）

RoCE v2 将 RDMA 跑在标准以太网上，降低了组网成本，适合不完全具备 InfiniBand 条件的数据中心。400G RoCE 在部分场景下已接近 InfiniBand HDR 的性能，但需要精心调优 ECN/PFC 拥塞控制参数，以避免 PFC（Priority Flow Control）造成的死锁和拥塞扩散问题。

### 3.5 通信优化实践

字节跳动 MegaScale 论文披露了其万卡集群的网络优化策略：
- **ECMP 哈希冲突缓解**：将 400G 下行链路分成两个 200G 端口（使用 AOC 电缆），8 个 200G NIC 以多轨方式连接到 8 台不同交换机，减少哈希不均衡
- **拥塞控制**：结合 Swift 与 DCQCN 原理，将精确 RTT 测量与 ECN 快速响应结合，显著提高吞吐量
- **通信与计算重叠**：AllGather 与前向传播重叠，ReduceScatter 与反向传播重叠，隐藏通信时间

## 四、混合精度训练与 FP8 最新进展

### 4.1 精度发展脉络

LLM 训练的精度策略经历了 FP32 → FP16/BF16 → FP8 的演进。BF16 因指数位与 FP32 相同（8位），动态范围与 FP32 相当，梯度下溢风险低，成为当前训练的事实标准（如 LLaMA、GPT 系列均用 BF16 训练）。FP16 在大模型训练中因动态范围不足容易出现梯度下溢，逐渐边缘化。

### 4.2 FP8 的突破与挑战

FP8（8位浮点）将存储和通信带宽需求降低至 BF16 的 1/2、FP32 的 1/4，在 H100/B200 等新架构上获得硬件支持。但 FP8 面临两大核心挑战：

- **精度损失**：FP8 指数位仅 5 位（E5M2 格式）或 4 位（E4M3 格式），动态范围和精度显著降低，可能导致训练发散
- **张量缩放（Tensor Scaling）**：通过动态或静态缩放因子将参数映射到 FP8 可表示范围，是解决精度损失的关键技术

### 4.3 2024–2025 年 FP8 进展

- **FP8-LM**（Microsoft, 2023）提出了三层 FP8 混合精度框架，将 FP8 应用在前向、反向的计算操作，同时保留 BF16 用于优化器状态和关键梯度，已在 H100 集群上将万亿参数模型可训练规模翻倍
- **Unified FP8 RL**（LMSYS, 2025）：将端到端 FP8 管道扩展到强化学习训练和采样阶段，在 RL 流程中平衡稳定性与性能
- **Scaling FP8 to Trillion-Token LLMs**（2024）：揭示了万亿 token 规模 FP8 训练中的关键不稳定问题，需配合精细的学习率调度和张量缩放策略
- **H100/B200 原生 FP8 支持**：新硬件通过 SFU（Scaling and Fused Multiply-Add 单元）实现高效 FP8 运算，混合精度框架下 BF16 + FP8 组合逐渐成熟

## 五、故障容忍与弹性训练

万卡级集群训练周期长达数周，硬件故障几乎是确定性事件。故障容忍设计直接决定有效训练时间占比（Arrangement Efficiency）。

### 5.1 故障检测与自动恢复

字节跳动 MegaScale 论文披露其在 12,288 GPU 上的实践经验：

- **守护进程心跳机制**：每个节点运行守护进程，定期向驱动进程发送心跳，携带 GPU 状态、RDMA 流量指标、错误日志等多维信息
- **多级监控**：二级监控评估整体健康状况（ECN/PFC/QoS 配置、链路抖动），毫秒级监控确定网络拥塞程度
- **自动诊断测试**：主机内回环测试、RNIC 对 RNIC 测试、NCCL AllReduce 基准测试，平均耗时 <10 分钟完成故障定位
- **90%+ 故障自动恢复**：生产运行数周内经历 100+ 次训练重启，90% 以上由系统自动检测、定位并恢复，从检查点恢复到追回训练进度约 15 分钟

### 5.2 两阶段检查点机制

MegaScale 采用两阶段检查点策略：

- **阶段 1**：GPU 写入主机内存（Pinned Memory），配合优化序列化机制，耗时仅数秒
- **阶段 2**：后台异步进程将状态传输到分布式存储（HDFS/COS），不阻塞训练

同数据并行组 GPU 共享状态分区，指定单个工作器读取后广播给组内其他工作器，有效缓解存储系统带宽瓶颈。

### 5.3 弹性调度

- **TorchElastic**（PyTorch）：支持从部分节点恢复训练，当节点故障不可用时可缩减 world size 继续训练
- **Elastor**（ACM, 2024）：支持部分 GPU 不可用时的弹性模型切分与训练恢复
- **Resilio**：结合故障感知调度能力，实现自适应弹性资源分配，提高大规模集群 GPU 利用率
- **PyTorch Distributed Checkpoint**：支持 GPU 计算与 checkpoint 写入并发执行，异步非阻塞

## 六、万卡级集群训练实践

### 6.1 MegaScale 架构

字节跳动 2024 年公开的 MegaScale 论文描述了其在 12,288 个 GPU 上训练 175B LLM 的生产系统，实现 55.2% MFU（Model FLOPs Utilization），比 Megatron-LM 提升 1.34 倍。

**核心设计原则**：
1. **3D 并行为基础**：TP×PP×DP 混合并行，在每个维度选择最优切分策略
2. **通信与计算重叠**：通过虚拟_pipeline_parallel_size（vPP）等技术减少流水线气泡
3. **数据流水线优化**：同机器内 GPU 共享张量并行组输入，避免数据加载器冗余竞争

### 6.2 数据 Pipeline 优化

- **异步数据预处理**：预处理不在训练关键路径上，GPU 同步梯度时可并行开始下一轮数据处理
- **两层树状数据加载**：每台机器一个专用数据加载器读入共享内存，每个 GPU 复制必要数据，减少数据加载器竞争瓶颈
- **分布式缓存**：训练数据预加载至内存/SSD 缓存池，通过 RDMA 直接读取，I/O 延迟从毫秒级降至微秒级

### 6.3 负载均衡

- **NCCL 微调**：调整重传定时器和重试次数参数，配合 NIC 自适应重传（adap_retrans）功能
- **计算负载均衡**：识别并隔离"计算落后者"——特定主机前向计算比其他等级慢约 10%，隔离后 MFU 提升 0.7%
- **网络拓扑感知调度**：策略性将数据密集型节点调度在同一 ToR 交换机下，减少跨交换机通信

## 七、国产分布式训练方案

### 7.1 华为 MindSpore + 昇腾

MindSpore 是华为推出的全场景 AI 计算框架，与昇腾 NPU 深度协同，其分布式训练的核心优势：

- **自动并行策略**：用户声明式开发，框架自动搜索最优并行策略，降低分布式配置门槛
- **多维度并行**：支持数据并行、模型并行（流水线）、optimizer parallel 等多种策略组合
- **昇腾 NPU 适配**：针对昇腾 910 系列芯片优化，在国产 AI 芯片中生态最完整
- **MindFormers**：面向大模型的套件，支持 LLM 预训练与微调的分布式部署

**局限**：相比 PyTorch 生态，MindSpore 的第三方工具链和社区资源相对有限，大模型适配的成熟度仍在快速追赶中。

### 7.2 百度 PaddlePaddle

PaddlePaddle（飞桨）是国内最早开源的深度学习框架，分布式训练能力：

- **分布式Fleet API**：提供统一的分布式训练高层 API，封装 DP、PP、TP 等并行策略
- **PipelineParallel**：支持流水线并行训练，降低大模型显存需求
- **多维度并行扩展**：结合飞桨推理引擎，为百度文心大模型训练提供基础设施支撑
- **GPU/NPU 异构支持**：支持 CUDA 和昆仑芯等国产 AI 芯片

### 7.3 阿里云 PAI（Platform for AI）

阿里云 PAI 是企业级机器学习平台，提供从数据处理到模型训练的一站式服务：

- **PAI-DSW**：交互式建模环境，支持多卡分布式训练
- **PAI-EAS**：在线模型服务，支持弹性扩缩容
- **PAI-DLC**：容器化的深度学习训练环境，兼容 PyTorch、TensorFlow 等框架
- **千问（Qwen）基础设施**：支撑 Qwen 系列大模型的训练与推理，在 MoE 架构、RLHF 训练管道上有深厚积累

阿里云 2024–2025 年持续加大 AI 基础设施投入，结合通义实验室的大模型研发，形成了从底层算力到上层应用的完整训练栈。

## 总结

2024–2025 年，大模型分布式训练技术进入系统性成熟阶段。**三大并行策略**（DP/PP/TP）的组合使用已成为万卡集群的标准范式；**DeepSpeed ZeRO-3、Megatron-LM、FSDP2、ColossalAI** 各有所长，生态竞争与合作并存；**通信硬件**（NVLink/InfiniBand/RoCE）的带宽升级和 NCCL 通信优化是性能突破的关键；**FP8 混合精度**在 H100/B200 硬件上加速落地，但仍需张量缩放等精细调优；**故障容忍**从"手工恢复"进化到"自动检测+快速恢复+弹性调度"，有效训练时间比率突破 90%；字节跳动 MegaScale 等实践验证了万卡级训练的工程可行性。

国产框架（MindSpore、PaddlePaddle、PAI）在自主可控的政策驱动下快速迭代，与昇腾、昆仑芯等国产芯片的协同是未来重要的技术方向。
