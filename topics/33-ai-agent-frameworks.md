# AI Agent 架构与框架：技术全景报告

**研究日期：2026-04-08**
**覆盖范围：2024–2025年主流技术进展**

---

## 一、Agent 架构核心组件

现代 AI Agent 的通用架构围绕四大核心模块构建：**规划（Planning）、记忆（Memory）、工具使用（Tool Use）** 以及 **协作（Multi-Agent）**，部分框架将 **反思（Reflection）** 作为独立模块。2024年 IBM 与微软研究人员发表的综述论文将此框架系统化，成为当前 Agent 设计的理论基石。

### 1.1 规划（Planning）

规划模块负责将复杂目标拆解为可执行的子任务序列，是 Agent 能否完成复杂任务的关键。主流规划方法包括五类：任务分解（Task Decomposition）、多计划选择（Multiple Plan Selection）、外部模块辅助规划、外部计划复用，以及基于记忆增强的规划（Memory-Augmented Planning）。2024–2025年的显著进展是 **PLaG（Plan Like a Graph）** 方法——将计划建模为有向图，允许多个步骤并行执行，而非线性串联，大幅提升复杂场景下的规划效率。

规划模块的另一核心能力是 **自适应规划**：Agent 在执行过程中持续接收环境反馈，动态调整后续计划，而非僵化执行预设路径。这要求规划模块与记忆模块深度集成，能根据中间结果修正全局策略。

### 1.2 记忆（Memory）

记忆系统通常分为三层：**工作记忆**（Working Memory，维护当前任务的即时上下文）、**情景记忆**（Episodic Memory，存储历史交互片段）、**语义记忆**（Semantic Memory，存储结构化知识）。微软2024年提出的 **Chunking and Chaining** 技术将对话切分为可管理的片段，通过相关性链接组织，使 Agent 能在跨会话场景中保持上下文连续性。

长期记忆的实现依赖向量数据库与知识图谱的结合。检索阶段通常采用混合策略：关键词匹配 + 语义相似度排序 + 结构化查询，多阶段逐步精炼结果。值得注意的是，当前主流框架在长期记忆容量与检索效率之间仍存在权衡——Reflexion 等系统使用滑动窗口机制，在效率与容量之间取折中。

### 1.3 工具使用（Tool Use）

工具使用使 Agent 能与外部系统交互，是其从"对话生成器"升级为"任务执行器"的核心能力。工具的定义边界极广：API 调用、代码执行、数据库查询、网页浏览、文件操作均可抽象为工具。

**ReAct（Reasoning + Action）** 是工具使用领域最具影响力的范式——Agent 先针对任务形成推理思考，再基于思考执行动作并观察结果，形成"思考→行动→观察"的循环。ReAct 在 HotpotQA 数据集上将幻觉率控制在 6%，相比纯 Chain-of-Thought 的 14% 有显著改善。**RAISE** 在 ReAct 基础上增加模拟人类短期/长期记忆的机制，在长对话场景中展现出更强的上下文保持能力。

2024–2025年的重要趋势是 **MCP（Model Context Protocol）** 的崛起。MCP 由 Anthropic 主导提出，正在成为 Agent 与外部工具交互的事实标准协议，解决了此前工具调用接口碎片化的问题——每个 MCP Server 定义一组工具，Agent 通过统一协议调用，使工具生态的互操作性大幅提升。同时，围绕 MCP 的安全研究也在快速跟进，包括数据泄露防护、工具污染攻击检测等。

### 1.4 协作（Multi-Agent）

多 Agent 架构分为 **垂直架构**（Vertical，含领导 Agent，其他 Agent 向其汇报）和 **水平架构**（Horizontal，所有 Agent 平等协作）两类。**MetaVerse** 通过"招聘→协作决策→独立行动→评估"四阶段循环，动态调整团队构成。**MetaGPT** 则要求 Agent 生成结构化文档输出而非自由对话，通过发布-订阅信息共享机制减少协作噪声，在 HumanEval 和 MBPP 基准上取得显著提升。

一个关键发现：组织化的领导 Agent 能使团队任务完成速度提升近 10 倍，且动态团队结构（根据任务需要引入/移出 Agent）优于固定团队配置。

## 二、主流 Agent 框架对比

### 2.1 LangChain / LangGraph

LangChain 是最早被广泛采用的 Agent 开发框架，提供 Prompt 工程、数据源集成、工具调用和记忆管理的模块化封装，GitHub 下载量已突破 10 亿次。

LangGraph 是 LangChain 生态中专注于 **有状态多步工作流** 的组件，基于有向状态机实现，支持循环、分支和条件判断。每个节点可访问和更新共享状态（工作记忆、对话历史），类型系统推荐使用 Pydantic 强类型定义，显著提升可调试性。LangGraph 的 `.get_graph().draw_ascii()` 可视化功能对调试复杂状态流尤为实用。

**定位**：LangChain 适合快速构建单步/链式应用；LangGraph 适合需要状态管理、循环和多 Agent 协调的复杂系统。

### 2.2 LlamaIndex Workflows

LlamaIndex 的核心竞争力在于 **文档索引与检索优化**，其 Workflows 功能采用事件驱动架构（与 LangGraph 的图驱动不同），适合编排复杂 RAG 或 Agent 工作流。2024–2025年 LlamaIndex 持续深化 Agentic RAG 能力，使 Agent 能在检索过程中主动决定是否需要调用外部知识、调用哪些知识源，而非被动依赖固定检索流程。

**定位**：以数据检索为核心场景的首选；与 LangChain/LangGraph 互补而非直接竞争。

### 2.3 AutoGen

微软推出的 AutoGen 以 **多 Agent 对话编排** 为核心，提供模块化的 Agent 交互规则配置。其默认配置包含 User Agent（接收用户指令）和 Assistant Agent（生成/执行代码）两种角色，天然适合代码自动化场景，并支持人类在循环中（Human-in-the-loop）介入指导。

**局限**：非程序员上手门槛较高，复杂本地 LLM 部署配置繁琐，对非软件领域场景的适配性有限。

### 2.4 CrewAI

CrewAI 引入 **角色化团队协作** 理念，每个 Agent 拥有明确角色、目标和权限，通过动态任务分配和冲突解决机制模拟人类团队工作方式。例如软件开发场景中，可配置需求分析师、设计师、编码者等多个角色 Agent 协同完成项目。

CrewAI 原生支持任务队列和动态任务分配，但不支持原生循环机制（while/loop），多 Agent 间状态共享能力较弱。**定位**：适合模拟组织行为、跨领域问题解决的场景，而非需要复杂状态管理的系统。

### 2.5 Dify

Dify 是国内最活跃的开源 Agent 应用开发平台，提供 **低代码/零代码** 的可视化编排界面，支持 RAG 流程编排、Agent 定义、工作流设计。Dify 的优势在于国内生态完善、部署简便、社区活跃，适合快速原型验证和中小规模生产部署。

**局限**：高度定制化场景受限于可视化编排的灵活性，多 Agent 深层协作能力不如 LangGraph。

### 2.6 框架综合对比

| 维度 | LangGraph | LlamaIndex | AutoGen | CrewAI | Dify |
|------|-----------|------------|---------|--------|------|
| 状态管理 | ★★★★★ | ★★★ | ★★★ | ★★ | ★★ |
| 多 Agent 协作 | ★★★★★ | ★★★ | ★★★★ | ★★★★ | ★★★ |

## 三、2024–2025 框架进展：推理、内省与自我修正

### 3.1 复杂推理能力提升

GPT-4、Claude 3.5、Gemini 等基础模型的推理能力提升，使 Agent 在复杂多步任务中的成功率大幅提高。**LATS（Language Agent Tree Search）** 受蒙特卡洛树搜索启发，通过树结构协同规划、行动与推理——状态表示为节点，采取行动视为节点间遍历，利用语言模型驱动的启发式评估选择最优路径，实现显著的自我反思推理能力提升。

### 3.2 内省（Introspection）

内省能力指 Agent 监控自身推理过程、识别逻辑错误的能力。**Reflexion** 通过语言反馈机制实现自我反思：利用成功状态、当前轨迹和持久记忆等指标，结合 LLM 评估器提供具体反馈，在提升成功率的同时减少幻觉发生。微软 2024 年的研究进一步推动了"元认知"模块的工程化——Agent 不仅执行任务，还能评估自身的置信度和不确定性。

### 3.3 自我修正

自我修正能力使 Agent 能在执行中发现错误并回退重来。ReAct 的"观察→调整"循环是最基础的自我修正形式；更高阶的形式如 **AgentVerse** 的评估阶段——每个 Agent 团队执行后，系统评估任务完成质量，若未达标则重新招聘 Agent、调整策略，形成完整的自我优化循环。

## 四、自主 Agent 的工程挑战

### 4.1 状态管理

随着 Agent 任务跨度和对话轮次增加，状态管理成为最难解决的工程问题之一。典型挑战包括：对话历史过长导致上下文溢出、状态在多 Agent 间传递的一致性问题、以及长时间运行后状态积累导致的内存压力。

LangGraph 通过 Pydantic 强类型状态定义和状态机模型，在工程层面提供了较完善的解决方案；而 CrewAI 和 Flowise/Langflow 仍在状态共享和长期记忆方面存在明显短板。实践中，**状态卸载（State Offloading）**——将非即时状态转储到外部存储——成为缓解内存压力的主流策略。

### 4.2 错误恢复

Agent 执行链条中的每个节点都可能出错：LLM 推理偏差、工具调用失败、网络超时、外部 API 异常。健壮的错误恢复机制需要：重试策略（指数退避）、降级方案（工具不可用时的替代路径）、以及最大步数限制（防止 Agent 进入死循环）。

AutoGen 内置了基础的错误恢复和对话管理机制，但深度定制仍需开发者自行实现。LangGraph 的条件分支支持使"错误→回退"逻辑易于表达，是当前最灵活的错误处理框架。

### 4.3 上下文窗口管理

Agent 处理复杂任务时，一次交互可能涉及 50+ 次工具调用，上下文窗口迅速膨胀。**Context Engineering** 已从"如何设计最佳 Prompt"演进为"如何管理 Agent 的上下文生命周期"。

主流策略包括：**摘要式压缩**（将历史信息压缩为摘要）、**选择性检索**（只加载与当前任务最相关的上下文片段）、**分层存储**（即时信息放工作记忆，次要信息放向量数据库）、以及 **CEA（Context Engineering Agent）** 等研究系统提出的智能上下文负载均衡方案。

## 五、Agent 评估

### 5.1 核心评估维度

Agent 评估尚未形成统一标准，学术界和工业界普遍关注以下维度：

- **任务成功率（Task Success Rate）**：Agent 是否最终完成了给定目标，是最直接的评估指标
- **工具调用准确率（Tool Call Accuracy）**：Agent 是否正确调用了所需工具，参数是否准确
- **幻觉率（Hallucination Rate）**：Agent 生成的内容与事实/工具描述不符的比例
- **执行效率**：完成任务所需的平均步数、时间和 Token 消耗
- **鲁棒性**：面对异常输入、工具失效时的稳定性

### 5.2 主流基准测试

GAIA（General AI Assistants）数据集是 2024 年最具影响力的 Agent 评估基准，涵盖需要多步推理和工具调用的真实世界任务。WebArena、Tau Bench 等则聚焦于网页操作和特定领域的 Agent 能力评估。ReAct 在 HotpotQA 上的幻觉率（6% vs CoT 的 14%）是一个有代表性的单项指标。

**根本性挑战**：现有基准测试难以跟上模型能力的发展速度，且静态测试集存在数据污染风险。动态基准和合成基准正在探索中，但尚未形成工业级标准。

## 六、安全 Agent 设计

### 6.1 约束执行（Constrained Execution）

当 Agent 拥有执行外部操作的能力时，约束其行为边界成为首要安全需求。MCP 协议层面引入了 **细粒度工具权限控制**——Agent 只能调用被明确授权的工具集，且每次调用都经过权限校验。OWASP 2024 年发布的 Agent 安全风险清单将"工具滥用"列为首要威胁，推动了 MCP 网关级安全方案（如 Permit MCP Gateway）的发展。

### 6.2 权限控制

零信任（Zero Trust）架构正在被引入 Agent 权限体系：每个工具调用请求都需独立验证，不依赖初始连接的隐式信任。Cerbos 等授权引擎提供基于属性的细粒度权限控制（ABAC），可动态判断 Agent 在特定上下文下是否有权调用特定工具。

### 6.3 审计日志

生产环境的 Agent 系统必须具备完整的操作审计能力：记录每个工具调用的发起时间、调用参数、返回结果和执行状态。微软的 **Agent Governance Toolkit** 覆盖了 OWASP 列举的 10 大 Agent 安全风险，提供 9500+ 测试用例，是当前最完整的 Agent 治理工具集。

MCP 安全最佳实践框架（2024）定义了七大理安全支柱：**身份认证、授权管理、输入验证、沙箱隔离、限速熔断、审计日志、漏洞管理**。企业级部署需在 MCP 网关层面统一实施，而非分散在各个 Agent 实现中。

## 总结与趋势

AI Agent 架构在 2024–2025 年完成了从"单步问答"到"自主任务执行"的关键跨越。核心趋势包括：

1. **框架趋同**：LangGraph 的状态机范式和 LlamaIndex 的事件驱动范式正在融合，主流框架对多 Agent 协作、状态管理、工具生态的支持趋于完善
2. **协议标准化**：MCP 的崛起有望终结工具调用接口碎片化，推动 Agent 生态互联互通
3. **安全优先**：随着 Agent 部署规模扩大，安全设计从"事后考虑"变为"架构内置"，零信任审计和约束执行成为生产级系统的标配
4. **评估体系成熟**：GAIA 等真实世界基准的建立，正推动 Agent 能力评估从"定性描述"向"定量测量"演进

Agent 技术的核心矛盾仍未解决：**自主性越强，可预测性和可解释性越低**。如何在扩大 Agent 能力边界的同时，建立有效的安全保障和可靠性验证机制，是接下来最值得关注的工程与研究课题。
