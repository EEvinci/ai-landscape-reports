## 一、从提示词工程到上下文工程

传统 Prompt Engineering（提示词工程）假设"写好指令就能解决一切"，但随着模型在生产环境中的大规模部署，这一范式的局限性暴露无遗：有限的上下文窗口迫使开发者在"相关性"与"完整性"之间做出不可能的权衡，而盲目的上下文堆积反而导致模型被矛盾信号干扰。

**Context Engineering（上下文工程）** 正是对这一困境的系统性回应。Andrej Karpathy 将其定义为："将恰好适量的信息填充进上下文窗口，以完成下一步任务的艺术与科学。"它不只关注提示词本身，而是对输入模型的所有信息——系统指令、会话历史、检索知识、工具定义、元数据、示例等——进行系统性设计、管理和优化。

**三层架构**是上下文工程的核心组织原则：
- **系统层**：角色设定、输出风格、安全边界（Policy/Tone）
- **任务层**：逻辑目标、行动指令（Logic/Objectives）
- **用户层**：即时请求、个性化偏好（Immediate Requests）

这一分层结构让上下文具备了**自适应能力**，可随任务类型、用户角色、会话状态动态调整。

## 二、主流推理框架：让模型思考得更深

### 2.1 Chain-of-Thought（CoT，思维链）

**核心思想**：引导 LLM 在给出最终答案前先生成一系列中间推理步骤，模仿人类逐步思考的过程。通过在提示中包含示例，展示如何一步一步推理，而非直接输出结论。

**优势**：
- 显著提升复杂推理任务（数学、逻辑、常识别）的准确性
- 增强可解释性，用户可见推理路径，便于发现与修正错误

**局限**：仅沿单一路径推理，无法处理需要探索多方案的问题。

### 2.2 ReAct（推理+行动）

**核心思想**：将"推理"与"行动"结合，使模型不仅能内部思考，还能调用外部工具（搜索、数据库、API）获取额外信息。

**工作循环**：思考（Thought）→ 行动（Action）→ 观察（Observation）→ 下一轮思考，循环直到问题解决。

**优势**：
- 获取实时外部知识，减少模型幻觉
- 动态适应环境反馈，适合知识密集型任务

### 2.3 Tree-of-Thoughts（ToT，思维树）

**核心思想**：对 CoT 的泛化，同时探索多条推理路径，形成树状结构。

**工作方式**：每步生成多个可能思路 → 评估可行性/潜力 → 使用 BFS/DFS 搜索树 → 支持回溯。

**适用场景**：没有单一解法路径的问题（如下棋、规划、创造性任务）。

### 2.4 Reflexion（反思）

**核心思想**：通过语言反馈实现自我改进。模型先执行任务、评估结果，若发现错误则生成反思注释（self-reflection），在下一次尝试中避免重蹈覆辙。

**典型流程**：执行 → 获得结果 → 自我评估 → 生成反思 → 重新执行。

该模式极大提升了 Agent 在长期任务中的鲁棒性。

### 2.5 Self-Ask（自我追问）

**核心思想**：模型主动判断当前问题是否需要分解，若需要则生成子问题、逐一回答，最后综合得出结论。

**典型模式**："这个问题是否需要拆解？" → "首先，让我回答这个子问题……" → "综合以上，我的答案是……"

这一模式与 CoT 互补，CoT 优化推理过程，Self-Ask 优化问题拆解。

## 三、高级提示工程模式

### 3.1 Few-shot Learning（少样本学习）

通过在提示中嵌入少量示例（通常 2-5 个），展示期望的输入输出模式，使模型无需额外训练即可理解任务要求。

**最佳实践**：
1. 从实际数据中收集代表性示例语料
2. 存入向量数据库，推理时动态检索最相关的示例
3. 注入提示而非预训练，减少 token 消耗

早期实验表明该方法可使准确率提升最高 30%，现代系统中收益可能更小，但对应用对齐仍有实质价值。

### 3.2 Structured Output（结构化输出）

要求模型输出严格遵循预定义格式（JSON Schema、XML、表格等）。

**关键实践**：
- 使用清晰的分隔符（`<user_query>` 等）结构化输入
- 定义 JSON Schema 约束输出字段
- 使用工具输出解析器规范化最终结果
- 采用 CamelCase 命名工具，减少 token 浪费

结构化输出是构建可靠 AI Pipeline 的基础，也是让模型输出可直接被程序消费的前提。

### 3.3 Constraint Prompting（约束提示）

通过显式规则限制模型的输出范围，包括：
- **内容约束**：定义可说什么、不可说什么
- **格式约束**：强制特定结构或长度
- **角色约束**：设定语气、专业水平、目标受众

约束提示常与安全边界结合使用，防止模型越界。

## 四、上下文窗口管理：有限空间，无限价值

### 4.1 稀疏注意力（Sparse Attention）

全注意力机制的 O(n²) 复杂度在长文本场景下成为瓶颈。稀疏注意力通过动态选择关键 Token 进行计算，显著降低内存与延迟。

代表方法：
- **MInference**（Microsoft）：识别 A形、垂直-斜线、块状三种稀疏模式，动态构建稀疏注意力，将长文本推理延迟降低最高 10 倍
- **MoA（Mixture of Sparse Attention）**：混合不同稀疏策略，自适应选择最优注意力模式
- **SCA（Selective Compression Attention）**：选择性压缩 KV Cache，在扩展上下文窗口的同时减少内存占用

### 4.2 选择性读取与 LongContextReorder

并非所有上下文信息都同等重要。**选择性读取**通过评分函数判断各片段重要性，优先保留高权重内容。

**LongContextReorder** 研究发现：最重要文档置于上下文开头或结尾，可使准确率提升约 22%。这一发现对 RAG 系统设计具有直接指导意义。

### 4.3 上下文压缩策略

| 方法 | 原理 | 效果 |
|------|------|------|
| **语义哈希摘要** | 将长文本压缩为语义等价的短摘要 | 保留核心信息，token 减少可达 60% |
| **重要性剪枝** | 用评分函数丢弃低权重片段 | 减少噪音，提升信噪比 |
| **Embedding 指针** | 用向量指针替代原文存储 | 节省存储，支持语义检索 |
| **对话摘要记忆** | 将历史对话压缩为关键要点 | ConversationSummaryMemory 可压缩 60% token |

**原则**：压缩优于穷尽——简洁的表示往往优于冗长的堆砌。

## 七、提示词安全：Prompt Injection 攻防全景

### 7.1 攻击面

Prompt Injection（提示词注入）通过在用户输入或外部数据中植入恶意指令，操纵 LLM 行为。2026 年 ScienceDirect 综述系统分析了 2022-2025 年间的 128 篇同行评审论文，揭示：

- 攻击已从**简单直接注入**演进到**多模态注入**（图像、音频、代码混合）
- 对无防护系统的成功率超过 **90%**
- 主要类型：
  - **直接注入**：在用户输入中嵌入系统级指令
  - **间接注入**：通过 RAG 检索的第三方文档注入恶意内容
  - **越狱注入**：绕过安全护栏获取模型违规能力
  - **多轮累积注入**：在多轮对话中逐步改变模型行为

### 7.2 防御策略

| 防御类别 | 方法 | 有效性 |
|----------|------|--------|
| **输入预处理** | 指令识别、语义过滤、注入模式检测 | 60-80% 检测率 |
| **架构级防御** | 角色隔离、指令-数据分离 | 最高 95% 已知模式防护 |
| **多 Agent 审查** | 专用 LLM Agent 协作审查输入/输出 | 对新型攻击有一定效果 |
| **基于对抗训练** | 重复攻击过程生成防御样本 | 对未见过的攻击向量防护有限 |

**关键发现**：架构级防御（让模型天然区分"指令"与"数据"）是最有前景的方向，但需要 LLM 底层架构创新，而非仅靠提示词层面的修补。

### 7.3 安全设计原则

- **最小权限**：上下文各层明确边界，防止跨层污染
- **输入验证**：在注入向量数据库前过滤恶意内容
- **输出审计**：对返回内容进行敏感信息脱敏与合规检查
- **可观测性**：记录所有 Prompt-Response 对，支持事后溯源
